# Brucia audit — 2026-10-29

## Conclusion

The repository now has a modular companion implementation, stricter hardware
availability handling and additional protocol/build/release regressions. **This
is not a production-readiness certificate.** The rebuilt firmware still needs
on-device acceptance tests; a fresh demo is intentionally deferred until then.

Baseline: commit `096de5de`, repository VERSION `0.1`. Changes in this audit are
made against that baseline. Test results below distinguish the rebuilt source
from the older firmware actually observed on hardware.

### Real hardware observation

Phone model A024, signed intermediate app `0.1`, LilyGO T-Embed CC1101 running
**firmware `0.8.23`**:

- App installation and USB connection succeeded; board/chip/firmware and live
  battery values appeared in the app.
- Device Info, Memory and Uptime commands returned real responses.
- Passive `wifi.ap` scanning delivered **7 unique APs** to the app.
- Raw logs/screenshots were kept outside tracked source; identifiers and nearby
  network names are not included in this report.

These observations do **not** validate the newly refactored firmware or the final
Android changes. Later ADB testing was blocked because the execution sandbox
could not start ADB's listener. Only the stock device is available; there are no
external tags, receivers, transmitters or expansion boards for positive loopback
and add-on tests.

The final firmware build used `tools/build_firmware.py` with the installed packages
read from a project-local build cache. Results: Cardputer 29.68 s, Core 4 MB
97.82 s, T-Embed CC1101 147.94 s. Native dependency warnings remain as described
below; the conflicting BLE scan-callback class warning is no longer present.

## Changes and resolved findings

| Area | Finding | Change |
|---|---|---|
| Structure | One companion file contained framing, probes, every radio handler and the session loop | Independent translation units and feature-owned command dispatch, with private state and explicit internal lifecycle APIs; see the [ownership map](../src/companion/README.md) |
| Reader | A 20 ms partial read discarded an incomplete prefix/payload and lost framing | Incremental bounded reader retains fragments, expires abandoned input and resets on mode entry |
| Loop scheduling | Non-blocking reads remove the old implicit wait | Explicit scheduler yield prevents an idle busy loop |
| Responses | CLI capture could exceed its intended buffer cap; escaped output could exceed the MTU | Capture is capped and oversized JSON responses produce a bounded ERR instead |
| Codec | Signed Base64 accumulator shifts could overflow; invalid characters were silently ignored | Unsigned accumulation, validation of characters/padding/tail bits, explicit rejection and native UBSan tests |
| App routing | An unknown ACK could consume an unrelated pending callback; ERR was ignored | Strict ID routing for ACK/ERR, negative completion for device/local errors |
| Reconnect | Request counters restarted for each client; closed reads could spin | Process-wide request IDs, connection identity checks, monotonic read deadline and immediate closed-transport return |
| Writes | Parallel writes were not explicitly serialized | Frame construction/send and physical USB writes are synchronized |
| App identity | HELLO and the Device footer used hardcoded versions | Both use BuildConfig.VERSION_NAME |
| Capabilities | Missing/invalid flags defaulted to present | Only literal true enables module-dependent tools; unknown names are rejected |
| Composite tools | Stream starts could bypass page gating and report running after rejection | Central stream capability checks, unique SUB IDs, timeout/error cleanup and state published before asynchronous IO |
| Probes | A saved PN532 setting/address ACK could be treated as physical presence; SPI begin could succeed by default | Quiet PN532 identification checks an actual firmware response; CC1101 and LoRa get identification/init probes |
| Fixed wiring | Standard SPI SCK/MISO aliases were swapped in the T-Embed header | Aliases agree with the board's SCK 11 / MISO 10 wiring |
| Optional tools | LF/iButton and unsupported external NFC operations appeared usable without confirmed support | Relevant companion controls are disabled when not confirmed; a PN532 does not imply an LF reader |
| BLE libraries | Independent classes shared the external name scanCallbacks; 2.x callbacks did not override the const signature | Distinct class names, version-aware signatures and compile/behavior regressions |
| Resource build | WebUI generation uploaded source to a remote minifier and could fail offline | Local, deterministic gzip generation with atomic writes and no source upload |
| Dependencies | Different cached NimBLE versions and malformed owner-qualified Arduino dependency names caused redundant downloads | Pin NimBLE 2.5.2; bootstrap direct dependencies and normalize known malformed manifests before recursive resolution |
| CI | Main checks did not run on PRs or changes outside selected paths | PR/push coverage, lint, native/build/release regressions, representative board matrix and manual full matrix |
| Release | Broad staging, stale signed APK reuse, inconsistent web manifest version and partial Git ref pushes | Explicit files only, clean-tree/signing checks, fresh APK build, version synchronization, metadata rollback before commit and atomic branch/tag push |
| Product identity | Some visible firmware labels/defaults still identified only Bruce | Shared Brucia identity for boot/About/CLI, BLE manufacturer and local WebUI; new-install AP/QR/mDNS labels; upstream attribution and file/command compatibility retained |
| Documentation | Historical checkmarks/builds were presented as current blanket proof | Current evidence is separated from historical and pending tests; Paparazzi fixture coverage is described accurately |

## Remaining release gates and known limitations

1. **On-device acceptance:** flash the rebuilt image, verify its reported version,
   then complete the [interactive controls checklist](APP_CONTROLS_CHECKLIST.md).
   Re-run USB reconnect, physical exit/input lock, screen-off/background service,
   Stop/cancellation and long-duration streaming on the final APK/firmware pair.
2. **Hardware stimulus/response:** audio needs measured capture/playback, IR needs a
   known signal/receiver, NFC needs suitable test tags and Sub-GHz needs a known
   source/receiver. Without those, command completion cannot prove RF/optical/audio
   operation. The [hardware contract](HARDWARE_CAPABILITIES.md) distinguishes chip
   identification from fixed onboard wiring and actual functional health.
3. **Update distribution:** the app requests the BruciaDev Releases API without
   authentication, while the repository was observed as private. That configuration
   cannot provide anonymous API access. Verify the intended release channel and
   download permissions without embedding a maintainer token. In-app installation,
   interrupted download/flash and recovery remain acceptance tests.
4. **Version/artifact baseline:** repository `0.1`, installed firmware `0.8.23` and
   the existing web manifest `0.6.3` differ. Historical firmware numbers must not be
   mistaken for the new release line. The release script synchronizes new builds;
   the currently hosted binary/manifest was not republished during this audit.
5. **Persistence upgrades:** Room still has fallbackToDestructiveMigration and no
   exported schema history. Before a database-version change, obtain historical
   schemas and add tested, non-destructive migrations; do not guess old schemas.
   This audit does not change the database schema/version.
6. **Native dependency warnings:** remaining NimBLE return-type, graphics ODR and
   audio-decoder bounds warnings need upstream/source review and malformed-media
   testing. A successful link does not establish that they are harmless; they were
   not globally suppressed. Other Git/semver dependencies remain unpinned.
7. **Transfer/stream acceptance:** test interrupted transfers, checksums, full/removed
   storage, long filenames/paths (including spaces), large captures and contention
   between mutually exclusive radio/audio streams. SUB error handling has unit-level
   support but still needs Android/USB failure injection.
8. **Coverage limits:** the app's large UI/ViewModel files and most real UI flows
   have not received exhaustive lifecycle/instrumentation tests. Historical
   Paparazzi fixtures are not tests of every production composable/control. The
   remaining lint warnings require individual triage rather than blanket suppression.

No release was published, no repository visibility was changed, and no new demo
assets were generated as part of these checks. A commit was attempted only as far
as staging; the sandbox rejected creation of `.git/index.lock`. Nothing was staged,
committed or pushed. Source changes and the handoff are left in the workspace.
