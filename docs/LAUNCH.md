# Launch: public repository

Status: **done 2026-11-09.** The repository is `1vcian/Brucia` (public), the site is
`https://1vcian.me/Brucia/` (wiki `https://1vcian.me/Brucia/wiki/`), and releases are published
there by `release.sh` through the git remote `origin`. The old private name is no longer used
anywhere in the configuration; GitHub redirects web, git and API requests from the old name, so
apps built before the rename still find new releases.

## The central config

`brand.json` at the repository root is the only place where Brucia's repository, site and
upstream credit links are written. The `launch` block now matches the public values.

| Consumer | How it reads `brand.json` |
| --- | --- |
| Firmware | `include/brucia_brand.h`, generated by `python3 tools/brand.py write` (committed). `include/brucia_identity.h` builds on it. Used by the companion screen and its release QR, Device Info, the `info`/`help` CLI, the serial banner, the default QR list, NFC default URLs and GPX metadata. |
| Android app | `android/app/build.gradle.kts` reads `brand.json` into `BuildConfig.BRAND_*`; `app/brucia/BrandLinks.kt` derives every URL (updater API, accepted release asset prefixes, wordlist downloads, wiki, About footer, default beacon SSID). |
| Website | `docs/brand.js`, generated (committed), loaded before `docs/release-catalog.js` and `docs/wiki/wiki.js`. |
| Managed text | Links in `README.md`, `SECURITY.md`, `docs/USAGE.md`, `docs/index.html`, `docs/wiki/index.html`, `wiki/*.md` and the WebUI `embedded_resources/web_interface/index.html` are rewritten in place by `tools/brand.py write`. |
| Release script | `release.sh` reads `python3 tools/brand.py get repo_slug` and `get release_remote`. |

`tools/test_brand.py` fails if a generated or managed file is out of date, if a brand macro is
used without its header, or if a `github.com/1vcian/...`, `1vcian.me/...`, Bruce site or Bruce
organisation link is hardcoded outside `brand.json` and the reasoned allowlist in that test.
It also performs the whole switch on a temporary copy, so the procedure below is tested before
it is used.

### Changing the repository or site again

1. Edit `github_repo` / `site_url` / `release_remote` in `brand.json` (and the `launch` block),
   keeping the old repository name in `accepted_release_repos` for as long as installed apps may
   still see asset URLs under it.
2. `python3 tools/brand.py write`, then `python3 tools/brand.py check` and the test suites
   (`python3 -m unittest discover -s tools -p 'test_*.py'`, `node --test tools/test_site_release.cjs`,
   `cd android && ./gradlew :app:testDebugUnitTest :app:lintDebug`).
3. Commit and run `./release.sh`. If publication fails after the release commit, fix the cause
   and run `./release.sh resume`: it republishes the same version from `.release-staging/`.

### Left from the rename

- No redirect from the old site path: before the launch only the owner ran Brucia builds.
- The CC1101 wiring QR codes in `src/core/settings.cpp` point at images in the upstream Bruce
  repository (`media/connections/`); repoint them to `BRUCIA_REPO_URL` once both images are in
  Brucia's repository.

  `BruciaSniffer` APs; BLE API (Bruce app compatibility) still advertises `Bruc`.
- NFC emulation default (no loaded NDEF) and PN532 BLE "Visit Brucia": the phone opens the site URL.
- GPS tracker GPX: `creator="Brucia"`, metadata link to the site.

## What keeps the Bruce name on purpose

- Credit and licence: `NOTICE`, `THIRD_PARTY.md`, "Based on Bruce" on Device Info, the WebUI and the
  site footer, the Bruce developers in the hidden credits, the "Bruce upstream" QR entry.
- Compatibility: SD-card folders (`/BruceRF`, `/BrucePCAP`, `/BruceJS`, ...), `Filetype: Bruce ...`
  file headers, `getBruceVersion` and other JS API names, the `bruce` RFID save format, release
  asset names `Bruce-<env>.bin`, the `/BruceWebUI` override folder, WebUI default credentials,
  the `Brucegotchi` feature and startup-app key, config keys and the internal `bruceConfig` names.
- Bruce app compatibility: the BLE API device name `Bruce`/`Bruc` (`src/modules/ble_api`).
- Libraries and metadata: `BruceHAL` (`lib/HAL/library.json`), `mquickjs` from the Bruce
  organisation, inherited board JSON vendor URLs, upstream PCB documents, inherited SD-card content
  (Bruce theme builder, example JS bookmarks) and the upstream WebUI customization guide.

## Documentation regeneration

Public documentation refreshed 2026-11-09 against the 0.1.11 source context. These
materials are prepared locally; this regeneration does not publish the site or wiki.
README, the nine core wiki pages (including Tutorials), feature-page verification
notes, sidebar/routes, usage guide and website copy now describe the public project.
Toolchain detail remains in CONTRIBUTING.md and wiki/Building.md; wire details remain
in proto/PROTOCOL.md rather than a second outdated command table.

Media: three real screen recordings of the signed 0.1.12 APK in an Android 36.1
emulator replace the six text-slide videos. They show category navigation, the
built-in synthetic WPA demo and actual Flipper/Proxmark3 dictionary imports.
Each video keeps the full app viewport with a small provenance banner above it,
a poster taken from the recording, captions and steps in wiki/Tutorials.md.
`docs/media/manifest.json` records the APK, raw capture and output hashes.
This is emulator evidence; radio/tag/USB effects are not demonstrated.

To package new captures, record the actual app with Android `screenrecord`, inspect
all results, then update the capture context/captions in the packager. Keep originals:

```sh
python3 tools/package_app_recordings.py PATH_TO_REAL_CAPTURES
python3 tools/brand.py check
```

`tools/render_public_media.py` now only regenerates the two still images from
illustrations and verified Compose fixtures; it preserves recordings and tutorials.
Those still images retain their fixture labels. Do not regenerate slide videos or
present fixture data as a physical device recording.
