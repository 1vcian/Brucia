## Summary

All 13 features were traced UI → ViewModel/service → command/stream (or phone-only DSP/proxy/scan)
→ gating → firmware handler (read only) → reply/stream → parsing → UI → cleanup.

The code is mature: parsers are bounded, streams are ON/OFF-symmetric with rotation-safe
re-binding, lists/buffers are capped, long operations are time-bounded with explicit Stop, and
texts are generally honest and hedged ("approximate", "authorized/lab use", "receiver reaction
unverified"). The MITM HTTP parser in particular is hardened against injection, smuggling and
resource exhaustion.

Two real defects were fixed with JVM tests that fail before and pass after:

1. **Network Scan — VulnRules regreSSHion range (accuracy / honest-framing, HIGH-confidence):**
   the OpenSSH CVE-2024-6387 rule matched 8.0-8.4 despite its own "8.5-9.7" label, telling users a
   patched server had a high-severity RCE. Regex corrected. Test `VulnRulesTest`.
2. **Tone — RTTTL parser divide-by-zero (LOW / hardening):** `b=0`/`d=0` headers produced
   `Int.MAX_VALUE` or negative note durations. Guarded to RTTTL defaults. Test `RtttlTest`. (Phone
   playback path uses native firmware RTTTL, so this is a preview-path hardening, not a crash users
   hit today.)

Follow-up (coordinator request, same day): the five open items B17-01..B17-05 were fixed — active
Wi-Fi selection with real prefix and a bounded scan plan, streaming MITM bodies with truncated-log
markers, HEAD/304 heads relayed unchanged, geo replay reporting the device's answer, and Bug Sweep
stream ownership. New tests: `WifiLanSelectorTest` 10, `MitmStreamingTest` 5 (loopback only),
`GeoReplayServiceTest` 4, `SweepStreamsTest` 3; `NetworkScanSessionTest` and the Network Scan
screenshot sample adapted to the host-list API (rendered text unchanged). None extends attack
capability. RF/radio behavior was not exercised; see the hardware checks above, plus: on a phone
with Wi-Fi + mobile data, Wi-Fi + VPN, and mobile data only, open Network Scan and MITM and confirm
the scan/start is refused with the matching reason except on plain Wi-Fi; on a /23 or larger Wi-Fi,
confirm the bounded-scan note; download a >4 MiB file through the proxy from an owned target.
